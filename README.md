# Retail Supply API

Backend-приложение для автоматизации закупок в розничной сети. REST API
поддерживает покупателей и поставщиков, каталог, корзину, заказы, импорт
YAML и фоновые задачи.

> Документация составлена по предоставленным URL-конфигурациям, моделям,
> сериализаторам, настройкам и Docker Compose. Перед публикацией сверьте
> её с актуальным кодом, особенно ответы и права доступа отдельных
> представлений.

## Возможности

-   Регистрация пользователей с ролями `buyer` и `supplier`.
-   Вход по имени пользователя и паролю с выдачей DRF token.
-   Получение профиля текущего пользователя.
-   Активация аккаунта по email через Djoser (отправка активационного
    письма включена).
-   Просмотр категорий и активных товаров.
-   Просмотр предложений поставщиков, цен, остатков и доступности.
-   Настройка поставщиком приёма заказов.
-   Асинхронный импорт YAML через Celery и Redis.
-   Проверка статуса импорта по `task_id`.
-   Экспорт каталога поставщика в YAML (в текущем коде доступен
    администратору).
-   Корзина, адреса доставки и оформление заказов.
-   Разделение корзины на отдельные заказы по поставщикам.
-   Контроль допустимых переходов статусов заказов.
-   Email-уведомления при настроенном почтовом backend.

## Технологии

Python 3.14, Django 6.1, Django REST Framework, Djoser, PostgreSQL,
Celery, Redis, PyYAML, Docker, Docker Compose.

## Требования

Для Docker-запуска необходимы Docker Engine, Docker Compose и свободный
порт `8000`. Для локального запуска без Docker также нужны Python,
PostgreSQL и Redis.

## Настройка

Скопируйте `.env.example` в `.env` и задайте собственные значения.
Обязательно замените `DJANGO_SECRET_KEY`, `DB_PASSWORD` и другие
демонстрационные значения. Не публикуйте `.env` и не добавляйте его в
Git.

## Запуск через Docker Compose

``` bash
docker compose build
docker compose up -d
docker compose ps
```

Проверка Django и миграций:

``` bash
docker compose exec web python manage.py check
docker compose exec web python manage.py showmigrations
```

Создание администратора:

``` bash
docker compose exec web python manage.py createsuperuser
```

Логи:

``` bash
docker compose logs --tail=100
docker compose logs web --tail=100
docker compose logs worker --tail=100
```

API доступен по адресу `http://localhost:8000/`, административная панель
--- `http://localhost:8000/admin/`.

Остановка:

``` bash
docker compose down
```

Команда `docker compose down -v` удаляет также том PostgreSQL и его
данные; используйте её только если действительно хотите удалить базу.

## URL-префиксы

  -----------------------------------------------------------------------
  Префикс                             Назначение
  ----------------------------------- -----------------------------------
  `/api/users/`                       Регистрация, вход, профиль

  `/api/auth/`                        Djoser: активация и операции с
                                      паролем

  `/api/catalog/`                     Категории, товары, импорт/экспорт,
                                      настройки поставщика

  `/api/`                             Корзина, адреса и заказы
  -----------------------------------------------------------------------

Подробности см. в [API_DOCUMENTATION.md](API_DOCUMENTATION.md).

## Авторизация

DRF настроен на `TokenAuthentication` и `SessionAuthentication`.
Эндпоинт `/api/users/login/` возвращает токен. Для защищённых запросов
используйте:

``` http
Authorization: Token <token>
```

Часть каталога доступна без авторизации. Операции корзины ограничены
покупателями, импорт и настройки магазина --- поставщиками.

## Импорт YAML

Поставщик отправляет файл `.yaml` или `.yml` в
`POST /api/catalog/import/` как `multipart/form-data`, поле `file`. Файл
не должен быть пустым, максимальный размер --- 2 МБ, содержимое должно
быть UTF-8. Задача ставится в Celery; статус проверяется через
`GET /api/catalog/import/status/<task_id>`.

Для структуры YAML используйте пример `shop1.yaml` из репозитория и
фактическую реализацию импортёра.

## Тестирование

``` bash
docker compose exec web python manage.py test users products orders
```

В ходе разработки этим набором ранее успешно проходили 56 тестов. После
изменений запускайте тесты повторно и ориентируйтесь на фактический
результат текущего запуска.

## Ограничения текущей конфигурации

-   Compose запускает Django через `runserver`; это конфигурация
    разработки/демонстрации, не production.
-   Экспорт YAML защищён `IsAdminUser`.
-   Маршруты товара по ID и статуса импорта в текущем URLconf объявлены
    без завершающего `/`.
-   Для реальной отправки писем требуется корректный SMTP backend.
